# GodotDevTools - Project Rules

Prompt in force: The Elite Software Master Prompt v1.1 - Annex A (Godot / game tooling)
Purpose in one line: Independent Godot 4 editor plugins + headless CLIs for developer testing and project health, each built on a single core operation.
Frozen foundation: for every tool, `addons/<tool>/core/` holds the one operation; the editor dock, the CLI and the tests call it and add no checking logic of their own. Module layout per tool: core / ui / cli (+ runtime where a tool has an in-game piece). No tool depends on another tool.
Build: none (interpreted GDScript) - Full gate: `sh tests/run_tests.sh <godot-binary>` - Test corpus: `demo/` fixture project + `tests/test_*.gd`
Budgets: each scan should finish in seconds on a mid-size project (Partially verified: on a synthetic 4,623-file project the worst scanner takes 4.4 s and the median is 147 ms; see docs/performance.md); no network use, ever; deterministic seeded randomness in the network simulator so CI reproduces the same bad network.
Coverage floors: every promised check has at least one fixture case and one test check; every CLI is exercised by the gate, including its exit-code-2 path where it has one.
Special rules for this project: Godot 4.3 is the verified version - never claim another version works without a test run; binary or unparsable files are quarantined and reported, never guessed; natural-language search is rule-based and offline by design, and its results must always state why they matched; simulation results must be reproducible from a seed.
Known limitations live at: README.md "Limitations and known issues" - Decision log: this file - QUALITY.md: QUALITY.md

CONTRIBUTING.md documents cutting a release.
- 2026-10-30: Contributor surface added: CHANGELOG.md (Keep a Changelog), CONTRIBUTING.md (the frozen core/ui/cli rule, gate, coverage floor, release process), issue templates (bug report asks for gate status; feature request asks where the logic would live) and a PR template with an evidence checklist.
- 2026-10-31: AI_USAGE.md added: the repo-aware guide for AI agents - a pasteable project prompt plus the file map, inspection order, demo-fixture index and the CLI reference transcribed from the code itself (defaults, fail-on kinds, exit codes), linked from README.md. Rule for it: when code and documentation disagree, the code wins and the docs get fixed.
- 2026-10-31: Suite expanded 9 -> 29 tools on the frozen architecture (pure core + thin dock + headless CLI + runtime where in-game, one fixture problem, one test suite, one exit-2 gate, one README per tool). Scope decisions kept honest: thermal_sim and batch_profiler report documented ESTIMATES (no devices/GPUs to measure here); shader_doctor is a static .gdshader analyzer - there is no graph-to-code compiler, and Godot's visual shaders compile to the same language so they are covered; l10n_matrix does no network/machine translation (in-context = preview data); test_runner is a generic discovery/planning/JUnit runner that detects GUT from text without depending on it (this repo's own gate stays run_tests.sh); seed_replay complements time_machine (state-snapshot rewinding) with PRNG/event-chain determinism verification; prefab_guard writes scenes only under explicit --apply; leak_hunter static findings are suspects, the runtime weakref watcher confirms. Suites 104 -> 292 checks.
- 2026-10-31: Roadmap expanded to 110 entries at Sean's request (60 new). Optional shared components (report schema, exporters, dispatcher, CI action) are allowed only as consumers of tool reports; no tool may import them, so the no-cross-dependency rule stands. Particle Budget Inspector and Object Pool Advisor built: both are static (scene-property capacities; pattern-read spawn sites) with explicit limits; the pool advisor's runtime counter supplies measured evidence but is unit-tested only.
- 2026-10-31: Roadmap expansion implemented through stacked PRs #21 to #40: 93 new addons (133 total) on the frozen core/ui/cli layout. Shells (plugin, dock, CLI) are generated from a uniform core contract (`run(input, options)` -> summary + issues; optional `artifacts` written by the CLI) so behaviour stays in core/. Shared components (report schema, exporters, dashboard, diff, suppressions, dispatcher, pre-commit, CI action) only consume reports. Tools that execute project code (scene smoke, load profiler, bench harness, mutation tester, save corruption, property tests, scenario runner) say so in their READMEs. Fixtures that would break Godot's import (the conflicted scene) sit behind `.gdignore`. Native accelerator: research note only, no native code. CI gate timeout raised from 180 s to 600 s for the larger suite.
- 2026-10-31: Added a dock smoke suite (`tests/test_docks.gd`, run in the gate) and a large-project benchmark (`tests/bench/`). The benchmark found a quadratic reference search in cleanup_workbench (18 s on 4.6k files, now 0.27 s) and per-line regex compilation in privacy_audit (6.2 s, now 1.9 s). In both cases the old and new full finding lists are identical. a11y_options at 4.4 s is the slowest scanner left; it is within budget, so it was not changed.
- 2026-10-31: Roadmap closed: all 110 entries are checked. Verification gained two CI sessions on Linux (Xvfb, Mesa llvmpipe). A real-editor session drives every dock through real mouse events, and a live-game session drives every runtime node. The live session found a seeded-RNG defect, now fixed. Three items that still listed future work were built: per-platform texture estimates, rendered subtitle layout, and pck attribution. The native crate stays unbuilt by decision. Hands-on Windows use remains the one unverified surface.
