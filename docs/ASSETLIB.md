# Asset Library + suite presets

## Suite presets (in-editor)

`addons/suite_presets` (`full`, `ci_only`, `mobile_perf`, `content`, `testing`) previews which plugins a profile enables and applies changes only with `--apply` (backing up `project.godot`). It avoids enabling the entire suite by default. See the addon README.

## Godot Asset Library publishing

`tools/assetlib/generate_assetlib.py` generates one submission JSON per addon from `plugin.cfg`. The checked-in `assetlib/*.json` files retain their original **local** zip names (`GodotDevTools-<folder>-<plugin version>.zip`) for compatibility; those names are not the GitHub Release asset names. The release tag and an addon's plugin version can differ.

For a particular release, generate metadata into a separate directory using the actual release tag. The tag below is only an example; it does not assert that a release exists:

```sh
TAG=v1.2.3  # replace with the intended vMAJOR.MINOR.PATCH release tag
WORK=$(mktemp -d)
python3 tools/assetlib/generate_assetlib.py --release-tag "$TAG" --out "$WORK/metadata"
python3 tools/release/build_archives.py --tag "$TAG" --out "$WORK/dist"
python3 tools/assetlib/generate_assetlib.py --release-tag "$TAG" --out "$WORK/metadata" --check
```

Each tagged JSON's `zip` matches the corresponding generated release archive, such as `GodotDevTools-AndroidExportAudit-v1.2.3.zip`; its `version` remains the version in that addon's `plugin.cfg`. The generator does **not** check whether a GitHub Release or asset actually exists. Verify the intended release and its archive URL before submitting at <https://godotengine.org/asset-library/>, then link the published Asset Library page from the tool README. The three Android addons are not in the existing v1.2.0 release.

The packaging script uses `tools/release/manifest.json`, the same mapping as the tagged metadata generator. Each direct child of `addons/` must be a listed addon directory with `plugin.cfg`; folder names use lowercase letters, digits and underscores, and asset stems use letters and digits. The script rejects duplicate names, case-colliding or non-portable paths, and symlinks. It packages the current working tree, including untracked files under addon directories, so use a clean checkout of the intended commit. It requires an absent or empty output directory and stages archives before placing them there. Each addon archive and the suite archive includes the repository's MIT notice as `addons/<tool>/LICENSE`; the script refuses a conflicting existing addon license. These improvements apply to newly built archives, not previously published releases. No tag, release, or Asset Library submission is created by either command.

To refresh and check the checked-in, untagged metadata after changing an addon or the manifest:

```sh
python3 tools/assetlib/generate_assetlib.py
python3 tools/assetlib/generate_assetlib.py --check
python3 tests/test_release_assets.py
```

The generator does not delete stale JSON files; `--check` reports them for manual review. A metadata output directory must be empty or previously generated by this tool. The release workflow runs the gate before building and publishing the archives; the offline test builds and compares every archive without publishing. To run the installation smoke locally, use `python3 tests/release_install_smoke.py --godot /absolute/path/to/godot-4.3`. The smoke passed locally with a minimal source-built Godot 4.3 template; the official Godot 4.3 CI job is configured to run it but has not yet tested these changes. It extracts both archive types and runs the Android export audit on synthetic inputs, covering one addon, not every addon or Android devices.
